# 证书管理页面规范

## 模块路径
`src/views/Certificates.vue`

## 功能描述
管理已申请的 SSL 证书，配置和执行证书部署。

## 页面结构

### 证书列表
| 列 | 说明 |
|----|------|
| 域名 | 证书覆盖的域名 |
| 部署服务器 | 已配置的目标服务器标签 |
| 状态 | 有效/已过期 |
| 剩余天数 | 距离过期的天数 |
| 过期时间 | 证书到期日期 |
| 操作 | 部署、一键重新部署、重新申请、删除 |

### 操作按钮

1. **部署**：打开部署配置对话框
2. **一键重新部署**：使用已保存的配置重新部署到所有关联服务器
3. **重新申请**：跳转到申请页面重新申请证书
4. **删除**：删除证书记录

### 部署配置对话框

#### 服务器部署配置
| 字段 | 类型 | 说明 |
|------|------|------|
| 服务器 | 下拉选择 | 选择已配置的服务器 |
| 证书路径 | 文本 | 远程服务器上的证书存放路径 |
| 私钥路径 | 文本 | 远程服务器上的私钥存放路径 |
| 私钥密码 | 密码框 | SSH 私钥的密码（如果有） |

**路径说明提示**：
- 证书路径：`这是远程服务器上的证书文件路径`
- 私钥路径：`这是远程服务器上的 SSL 证书私钥文件路径`

## IPC 通信

### 获取证书列表
```javascript
window.electron.ipcRenderer.invoke('cert:get-all')
```

### 添加部署配置
```javascript
window.electron.ipcRenderer.invoke('cert:add-deployment', 
  certId, serverId, certPath, keyPath, passphrase
)
```

### 执行部署
```javascript
window.electron.ipcRenderer.invoke('deploy:cert',
  certId, serverId, certPath, keyPath, passphrase
)
// 返回: { success: boolean, message?: string, error?: string }
```

### 获取已部署服务器
```javascript
window.electron.ipcRenderer.invoke('cert:get-deployed-servers', certId)
// 返回: DeployedServer[]
```

## 一键重新部署流程

```
用户点击"一键重新部署"
    ↓
显示确认对话框
    ↓
遍历所有已部署服务器配置
    ↓
依次调用 deploy:cert
    ↓
汇总结果并显示
```

## 部署状态反馈

- **成功**：绿色提示 "部署成功"
- **失败**：红色提示，显示具体错误信息
- **批量部署**：显示成功/失败数量统计

## 证书申请失败处理与递归保护

### 已记录问题

证书申请在“保存域名配置到本地”之后可能直接失败，并显示：

```text
Maximum call stack size exceeded
```

该错误发生在 DNS 验证/ACME 申请链路时，不能只在前端显示“申请失败”，必须保留主进程中的原始错误和申请阶段日志。

当前重点风险：阿里云 DNS 提供商在收到 `LastOperationNotFinished` 时会再次调用 `createRecord()`。该重试路径不得使用无上限的异步递归，否则持续返回该错误时会耗尽调用栈。

另一个已确认的调用栈溢出原因是 `@certd/basic` 默认使用相对路径 `./logs/app.log`。macOS 从 Finder 启动 Electron 时工作目录可能是 `/`，`streamroller` 创建日志目录失败后会递归调用 `mkdir()`，最终同样产生 `Maximum call stack size exceeded`。

### 处理要求

1. DNS 服务商的重试必须使用有上限的循环或显式重试计数，禁止无界的 `return this.createRecord(...)` 递归。
2. `LastOperationNotFinished` 应至少包含最大重试次数、重试间隔和最终失败信息；达到上限后返回可识别的业务错误。
3. ACME 依赖的日志目录必须位于可写的用户数据目录，不能依赖 macOS Finder 的当前工作目录。
4. `acme:apply` 必须将申请阶段、DNS 服务商和底层错误传递到进度日志及最终错误结果中。
5. 申请失败时不得写入成功证书、成功申请日志或成功的自动续期配置；DNS 清理应保持非阻断，但清理异常要记录。
6. 前端申请弹窗应保持在失败状态，并显示可执行的排查提示，例如检查 DNS AccessKey 权限、域名托管区域和 `_acme-challenge` 记录。

### 验收标准

- 模拟 DNS 服务商连续返回 `LastOperationNotFinished` 时，流程在配置的最大次数后结束，不出现 `Maximum call stack size exceeded`。
- macOS 从 Finder 启动客户端时，ACME 模块可以正常初始化，不因相对日志路径导致 `streamroller` 调用栈溢出。
- DNS/ACME 申请失败时，申请日志包含失败阶段和原始错误，且本地证书库不新增成功证书。
- DNS 验证超时、权限不足、重复记录和 ACME 服务错误均能在 UI 中看到具体原因。
- 申请成功路径仍能保存证书、申请配置并继续执行可选部署流程。

## DNS 凭据复用

### 目的

申请证书时，用户可按 DNS 服务商自动回填已验证的 AccessKey ID 和 Secret，避免重复输入；回填结果不得被一次失败申请中填写的错误凭据污染。

### 数据来源与优先级

1. 每张成功签发的证书都会在 `cert_apply_configs` 保存其 DNS 服务商和加密后的凭据。
2. 当用户选择 DNS 服务商时，客户端读取当前用户该服务商最近一次成功签发的配置，并回填到申请表单。
3. 该成功配置同时刷新服务商维度的本地缓存，用于没有成功历史的新服务商场景。
4. 申请草稿只保存表单恢复所需的数据，不能更新“常用凭证”或服务商缓存。
5. “常用凭证”下拉框优先展示当前用户成功签发过的服务商凭据；没有成功历史时才可显示本地暂存凭据。

### 状态约束

| 操作 | 可写入申请草稿 | 可写入已验证凭据/服务商缓存 |
|------|----------------|-----------------------------|
| 编辑申请表单 | 是 | 否 |
| 申请失败或取消 | 是 | 否 |
| ACME 成功签发 | 是 | 是 |

### 验收标准

- 已有阿里云成功证书时，选择“阿里云”可回填该成功配置，即使本地缓存中存在不同的未验证凭据。
- 一次使用错误 AccessKey 的申请失败后，再次选择该服务商仍回填最近一次成功配置。
- `aliyun`、`tencent`、`huawei` 的凭据缓存彼此隔离。
- UI 不在日志、提示或下拉选项中暴露完整 Secret。

## 注意事项

1. **路径区分**：
   - 证书路径/私钥路径 = 远程服务器上的路径
   - 本地SSH私钥 = 本地电脑上用于登录服务器的私钥（在服务器管理中配置）

2. **密码优先级**：
   - 部署配置中的私钥密码 < 服务器配置中的私钥密码

3. **部署记录持久化**：
   - 每次配置部署后会保存到 `cert_server_deployments` 表
   - 一键重新部署时从数据库读取配置
